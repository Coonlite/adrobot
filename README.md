# Adrobot

Небольшая оболочка над рекламным трекером Keitaro (Admin API v1). Две части:

1. **Создатель кампаний.** По названию, гео-коду и ID оффера создаёт в Keitaro кампанию с двумя потоками: первый ловит указанную страну и редиректит на Google, второй отправляет остальной трафик на выбранный оффер.
2. **Редактор кампании.** Добавляет и убирает офферы в потоке, считает доли (сумма активных всегда 100), позволяет закрепить долю, отменить правки и опубликовать их в Keitaro.

Стек: Python 3.12, FastAPI, Jinja2, HTTPX, SQLAlchemy 2 (синхронный, SQLite). Интерфейс на серверных шаблонах, без SPA.

## Запуск

Нужны Python 3.12+ и [uv](https://docs.astral.sh/uv/).

```bash
uv sync
cp .env.example .env     # впишите адрес и ключ Keitaro
uv run fastapi dev       # http://127.0.0.1:8000
```

Файл `.env`:

```
KEITARO_BASE_URL=https://<ваш-keitaro>/admin_api/v1
KEITARO_API_KEY=<ключ из админки Keitaro>
```

`.env` читается из папки, в которой запущено приложение. Файл базы `data/adrobot.db` создаётся сам при первом запуске.

Проверки:

```bash
uv run pytest            # тесты
uv run ruff check .      # линтер
uv run ruff format --check .
uv run pyright           # типы, strict
```

## Как пользоваться

- **`/`** — форма создания: название, гео (две буквы), оффер. Домен, группа и источник необязательные: выбор берётся из списков Keitaro, пустой выбор значит «не задавать».
- **`/campaigns`** — список локально известных кампаний. Рядом с каждой стоит состояние в трекере: `active`, `disabled`, `archived` (в архиве Keitaro) или `deleted` (в трекере её уже нет). Если списки Keitaro не удалось прочитать, метка не ставится и показывается уведомление.
- **`/campaigns/{id}`** — редактор. Кнопка **Fetch streams from KT** забирает потоки из трекера, остальные кнопки меняют локальное состояние, а **Push to KT** отправляет его в Keitaro.

### Правила редактора

- Строка оффера имеет статус `synced`, `pending` (добавлена, ещё не отправлена) или `removed`. Поток, в котором есть неопубликованные правки, помечен как `pending` (подсвечен), у него появляются **Push to KT** и **Cancel**.
- **Доли.** Сумма активных долей равна 100. Незакрепленные офферы делят остаток поровну, остаток от деления целых достаётся офферам с меньшим id. Удалённый оффер показывает 0.
- **Пересчёт** происходит только при добавлении, удалении или возврате оффера. Pin пересчёт не запускает.
- **Pin** фиксирует текущее значение доли оффера. Он не меняет доли остальных и не переводит поток в `pending`. Закреплённая доля остаётся при следующем пересчёте, остальные делят то, что осталось. Если при пересчёте закреплённых долей оказывается больше 100 (или меньше 100 без свободного оффера), добавление, удаление или возврат отклоняется и ничего не пишется.
- **Remove** оставляет строку со статусом `removed`, **Bring back** возвращает её в раздачу долей.
- **Cancel** возвращает строки к последнему опубликованному состоянию: неотправленное добавление удаляется, удалённые и возвращённые строки откатываются, закрепления тоже. Keitaro при этом не вызывается.
- **Fetch** заменяет локальное состояние тем, что есть в трекере, но не трогает строки с неопубликованными правками. Офферы, пропавшие в Keitaro, остаются локально как `removed`.

## Как это устроено

```
adrobot/
  api/        FastAPI-маршруты, форма создания, шаблоны ответов и уведомления
  keitaro/    клиент Admin API, сборка тел запросов, разбор потоков, проверка домена/группы/источника
  db/         модели, запись (правки, Push-протокол), миграции схемы
  domain/     чистая логика: деление долей, состояние кампании в трекере
  web/        Jinja-шаблоны и CSS
tests/        pytest: домен, БД, клиент, маршруты, гонки
```

### Что сделано нарочно

- **PUT всего потока.** В базе лежит документ потока в том виде, как его вернул Keitaro. В `PUT /streams/{id}` уходит его копия, в которой заменены только офферы и доли. Фильтры, редиректы и прочие настройки потока не теряются, даже если таблица их не показывает. Имена ключей берутся из ответа Keitaro, а не придумываются.
- **Push как протокол.** `begin_push` одним условным `UPDATE` занимает поток и снимает слепок строк, `PUT` уходит из слепка, `finish_push` публикует именно слепок. Правка, сделанная во время `PUT`, остаётся `pending`. Пока идёт Push, Cancel, Fetch и второй Push отклоняются. Если ответа от Keitaro нет (обрыв, таймаут), поток помечается `uncertain`: правки остаются неопубликованными, Cancel недоступен до Fetch, повторный Push безопасен.
- **Create не теряет следов.** Кампания и каждый поток пишутся локально сразу после того, как их принял Keitaro. Если создание остановилось на полпути, кампания видна в списке, а Fetch подтянет реальные потоки. Откат в трекере не выполняется автоматически.
- **SQLite под несколькими операторами.** Включены WAL и `busy_timeout`, транзакции записи берут блокировку сразу (`BEGIN IMMEDIATE`), чтения идут без блокировки. Нагрузочный стенд лежит в `scripts/contention.py` (в репозиторий не входит), аналог есть в тестах.
- **Схема файла БД.** `create_all` не меняет существующие таблицы, поэтому изменения схемы оформлены как шаги в `adrobot/db/migrate.py` с `PRAGMA user_version`.

### Какие вызовы Keitaro используются

`GET /campaigns`, `GET /campaigns/deleted`, `GET /campaigns/{id}/streams`, `POST /campaigns`, `POST /streams`, `PUT /streams/{id}`, `GET /offers`, `GET /offers/{id}`, `GET /domains`, `GET /groups?type=campaigns`, `GET /traffic_sources`, `GET /stream_types`, `GET /stream_schemas`, `GET /streams_actions`, `GET /stream_filters`, `POST /report/build`. Все они есть в документации Admin API на `{host}/admin/?object=adminApi`.

## Ограничения

- **Гео.** В Admin API нет списка стран, поэтому приложение проверяет только формат (две латинские буквы) и передаёт код в фильтр `country` первого потока. Неверный код Keitaro примет или отклонит сам.
- **Домен, группа, источник** выбираются из списков Keitaro и необязательны. Создавать их приложение не умеет.
- **Один оператор, один процесс.** Авторизации нет, база локальная. Параллельная работа нескольких вкладок защищена от гонок, но это не многопользовательская система.
- **Состояние в трекере** (`archived`, `deleted`) читается при каждом открытии списка и редактора, кеша нет.
